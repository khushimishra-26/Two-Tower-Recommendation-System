# Goodreads Book Recommendation System
### A Two-Tower Neural Retrieval Model with Metadata-Aware Item Representations

A neural recommendation system built on the **Goodreads-10k** dataset. The project explores implicit-feedback recommendation using a two-tower architecture: one network learns user representations, while another learns book representations enriched with categorical metadata. Recommendations are generated by ranking books according to the compatibility score between the two learned embeddings.

> **Project focus:** candidate retrieval, representation learning, implicit feedback, negative sampling, and top-\(K\) recommendation evaluation.

---

## 1. Problem Formulation

Explicit ratings are transformed into an implicit preference signal:

\[
y_{ui} =
\begin{cases}
1 & \text{if } r_{ui} \geq 4\\
0 & \text{otherwise}
\end{cases}
\]

where \(r_{ui}\) is the rating user \(u\) gave book \(i\).

The model is trained to rank books a user positively rated above sampled books with which that user has no positive interaction in the training data.

This reframes recommendation as a **ranking / retrieval problem**, rather than predicting the exact numerical rating.

## 2. Dataset and Feature Engineering

The notebook loads `ratings.csv` and `books.csv` from the Goodreads-10k public dataset.

### User–book interactions
- `user_id`
- `book_id`
- `rating`
- Binary implicit-feedback `label`

### Book metadata
- Language code
- Original publication year, grouped into decade buckets
- Primary author (first author in the source authors field)

Missing language, year, and author values are assigned explicit unknown representations. Categorical identifiers are converted into integer indices using `LabelEncoder`, which are then consumed by PyTorch embedding layers.

### Data partitioning
The interaction data is split into:
- 80% training
- 10% validation
- 10% test

The split uses stratification on the binary label and a fixed random seed (`42`) to preserve the positive/negative label proportions across partitions.

**Evaluation note:** this is a stratified random interaction split, not a chronological split or a user-held-out split. It therefore evaluates held-out interactions for users and items represented in the encoded dataset; it should not be interpreted as a full simulation of future-time or completely unseen-user performance.

## 3. Model Architecture

The model consists of two independently parameterized encoders that map users and books into a shared 64-dimensional latent space.

### User tower

The user tower uses a trainable embedding lookup:

\[
\mathbf{u}_u = E_U[u]
\]

where \(E_U \in \mathbb{R}^{N_U \times d}\) is the user embedding matrix and \(d=64\).

### Item tower

The item tower combines a book-ID embedding with a learned projection of book metadata.

First, categorical metadata is embedded:

\[
\mathbf{m}_i =
[\ E_L[l_i]\ ;\ E_Y[y_i]\ ;\ E_A[a_i]\ ]
\]

The notebook uses embedding dimensions:
- Language: 4
- Publication-year bucket: 4
- Primary author: 8

The concatenated metadata vector is passed through a feed-forward network:

\[
\mathbf{v}^{meta}_i =
W_2\,\mathrm{ReLU}(
\mathrm{LayerNorm}(W_1\mathbf{m}_i+b_1)
)+b_2
\]

The metadata projection has a 64-dimensional hidden layer and produces a 64-dimensional output. It is added to the book-ID embedding:

\[
\mathbf{v}_i = E_I[i] + \mathbf{v}^{meta}_i
\]

This additive fusion lets the item representation incorporate both collaborative identity information and descriptive metadata. Metadata can provide useful signals when an item has limited interaction history, although this implementation does not by itself establish performance on genuinely unseen books.

## 4. Scoring Function

For user \(u\) and item \(i\), the model computes a scaled dot-product score with user and item bias terms:

\[
s(u,i)=\frac{\mathbf{u}_u^\top\mathbf{v}_i}{\sqrt{d}}+b_u+b_i
\]

where:
- \(\mathbf{u}_u\): user embedding
- \(\mathbf{v}_i\): metadata-enriched item embedding
- \(b_u\): user-specific bias
- \(b_i\): item-specific bias
- \(d=64\): embedding dimension

The factor \(1/\sqrt d\) scales the dot product, while the biases allow the score to account for user activity tendencies and item-level popularity tendencies.

At retrieval time, item representations can be computed for the catalogue and scored against a user vector. Previously seen training items are masked before selecting the top-\(K\) results.

## 5. Training Methodology

### Positive interactions and negative sampling

For each positive user–book interaction, the data loader samples **10 negative books** that are not in that user's set of positive training interactions.

A training example therefore contains:
- One user ID
- One positive book ID
- Ten sampled negative book IDs

Negative sampling avoids evaluating every possible user–item pair during each training update. A sampled negative is an unobserved positive interaction in the training data; it is not necessarily a book the user explicitly disliked.

### Sampled softmax / InfoNCE-style objective

The notebook's default training path uses cross-entropy over one positive candidate and ten sampled negatives. The positive candidate is placed at index zero.

For a batch example:

\[
\mathcal{L}_{u} =
-\log
\frac{\exp(s(u,i^+)/\tau)}
{\exp(s(u,i^+)/\tau)+
\sum_{j=1}^{10}\exp(s(u,i_j^-)/\tau)}
\]

where:
- \(i^+\): positive book
- \(i_j^-\): sampled negative book
- \(s(u,i)\): model compatibility score
- \(\tau\): temperature (the notebook defaults to 1)

This is an InfoNCE-style sampled classification objective. It increases the relative score of the positive book compared with the sampled negatives. The notebook also contains an optional pairwise logistic-loss branch, but the default configuration uses the cross-entropy branch.

### Optimization configuration

## 6. Evaluation: Recall@K

The principal retrieval metric implemented is **Recall@20**, evaluated on held-out positive interactions.

For user \(u\):

\[
\mathrm{Recall@K}(u)=
\frac{|R_K(u)\cap P_u|}
{|P_u|}
\]

where:
- \(R_K(u)\): top-\(K\) recommended books after masking training-seen items
- \(P_u\): held-out positive books for the user

The reported aggregate is the mean of per-user recall values over users with held-out positives:

\[
\mathrm{MeanRecall@K} =
\frac{1}{|U_{eval}|}
\sum_{u\in U_{eval}}\mathrm{Recall@K}(u)
\]

### Why Recall@K?

Recommendation is a top-\(K\) retrieval task: users see a limited list, not a score for every book. Recall@K measures how many of the user's held-out positive items are recovered in that list. It is therefore useful for assessing candidate retrieval coverage. It does not measure ranking quality within the list or penalize irrelevant recommendations directly; metrics such as NDCG@K and Precision@K can complement it.

### Popularity baseline

The notebook implements a global popularity baseline:
1. Count positive training interactions per book.
2. Rank books by those counts.
3. Exclude books already seen by the user in training.
4. Evaluate Recall@20 on the same evaluation users.

The model's Recall@20 is compared with this baseline, with absolute and relative lift printed by the notebook. This comparison helps determine whether learned user/item representations provide value beyond recommending globally popular books.

## 9. Limitations and Future Work

The current notebook is a research prototype focused on neural candidate retrieval. Potential extensions include:

- **Temporal evaluation:** use chronological splits to better represent production recommendation.
- **Stronger cold-start evaluation:** hold out items or users explicitly and measure metadata-based generalization.
- **Richer item features:** incorporate genres, descriptions, and text embeddings where available.
- **Improved negative sampling:** experiment with popularity-aware, in-batch, or hard-negative sampling.
- **Ranking metrics:** add NDCG@K, Precision@K, and MAP@K alongside Recall@K.
- **Hyperparameter optimization:** study embedding sizes, temperature, negative count, learning rate, and regularization.
- **Serving and retrieval:** export item embeddings, use approximate nearest-neighbor search (e.g., FAISS), and expose recommendations through an API.
- **User-side context:** incorporate interaction history, recency, or additional user features rather than relying only on user ID embeddings.
- **Experiment tracking:** log configurations, losses, metrics, and checkpoints to make comparisons reproducible.

## Project Summary

This project implements a **metadata-aware two-tower neural recommender** for implicit Goodreads user–book interactions. It combines learned user and item embeddings, categorical book metadata, scaled dot-product scoring, sampled contrastive training, and Recall@20 evaluation against a popularity baseline.

The work demonstrates practical understanding of recommender-system formulation, embedding-based representation learning, negative sampling, neural optimization, and offline retrieval evaluation.
